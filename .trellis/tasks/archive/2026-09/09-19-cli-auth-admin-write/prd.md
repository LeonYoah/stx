# Auth 与管理员用户写命令

## 目标

继续现有 API 的 CLI 覆盖，为个人资料更新和管理员用户管理提供安全写命令，并使用本地 STX 服务完成创建、更新、权限检查、幂等重试和清理验证。

## 范围

本批包含 4 个接口：

- `PUT /api/v1/auth/profile`
- `POST /api/v1/admin/users`
- `PUT /api/v1/admin/users/:id`
- `DELETE /api/v1/admin/users/:id`

CLI 命令：

```text
stx auth profile update
stx admin user create
stx admin user update <id>
stx admin user delete <id>
```

## 需求

### 命令输入与输出

- 所有命令支持 `--namespace`、`--confirm`、`--idempotency-key` 和 `--confirmation-id`。
- 个人资料更新支持 `--email` 和 `--language`，至少提供一项。
- 创建用户支持用户名、昵称、邮箱和管理员标志；密码只能通过隐藏的终端输入或 `--password-stdin` 读取，不能放在命令参数中。
- 更新用户支持昵称、邮箱、启用状态、管理员状态和可选密码；布尔参数必须能够区分未传入和显式 `false`。
- 删除用户需要一次性确认编号，第一次调用返回影响说明和确认编号，第二次使用相同幂等键和 `--confirmation-id` 才执行。
- warning 和确认提示写 stderr，业务结果写 stdout；JSON、YAML、table、raw 和 `--pick` 继续使用公共输出实现。

### 服务端安全

- 个人资料、创建用户和更新用户按 R1 处理，要求显式确认和幂等键。
- 删除用户按 R2 处理，要求一次性确认编号；仍然禁止删除当前登录用户。
- 管理员用户操作继续由服务端管理员中间件限制，不能只依赖 capability 或 CLI 校验。
- 相同用户、操作和幂等键的相同请求返回原结果；不同请求复用同一幂等键返回冲突。
- 请求摘要不得保存密码原文，只包含密码的 SHA-256；审计和日志不能记录密码或密码哈希。
- 写操作要记录公共执行与审计信息，包含当前用户、请求编号、操作编号、结果和 CLI 来源。

### 真实验证

- 使用最新 `dist/stx` 和现有软连接连接 `http://127.0.0.1:17800`。
- 使用隔离命名空间和管理员账号创建测试用户，随后查询、更新、验证权限并删除。
- 验证普通用户无法调用管理员用户命令。
- 验证缺少确认、幂等重试、幂等冲突、R2 确认编号和稳定退出码。
- 验证测试结束后没有留下测试用户，现有管理员用户不被修改。

## 约束

- 不处理登录、退出和令牌接口，它们已有专用命令。
- 不修改前端，不处理用户导出，不增加批量用户操作。
- 不把密码放入命令帮助样例、stdout、stderr、日志、审计或公共执行正文。
- 保留现有网页调用方式；前端若缺少 CLI 安全 Header，不应因此失效。
- 禁止执行 `git restore`；需要回撤时先取得用户确认。
- 新增或修改的代码注释使用中英双语，中文在前。
- Git 提交信息使用中文。

## 验收标准

- [ ] 4 个接口均有可发现的 CLI 命令，并加入操作登记和路由报告。
- [ ] 密码只从隐藏终端或 stdin 读取，服务端请求摘要不含密码原文。
- [ ] R1、R2、管理员权限、幂等重试和冲突均有自动测试。
- [ ] 创建、更新、删除测试用户的真实 HTTP 流程通过，结束后完成清理。
- [ ] 审计记录可以关联操作、执行编号、当前用户和 CLI 来源。
- [ ] 定向测试、`go test ./...`、`go vet ./...`、构建、许可证和差异检查通过。
