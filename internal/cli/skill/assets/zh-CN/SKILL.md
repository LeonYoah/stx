# STX CLI

通过 `stx` 与远端 STX 服务交互。不要绕过 STX 直接登录服务器修改 SeaTunnel，也不要猜测未公开的 API 或命令。

## 开始前

1. 运行 `stx --help` 查看当前二进制提供的命令。
2. 运行 `stx namespace list` 和 `stx whoami` 确认目标环境与当前用户。
3. 运行 `stx capability list` 获取远端服务实际支持且当前用户可用的操作。
4. 运行具体命令的 `--help`，按帮助中的参数、影响说明和示例调用。

登录示例：

```bash
stx login --server http://127.0.0.1:17800
```

交互终端可以输入用户名和密码；自动化环境使用命令支持的非交互参数，不要把令牌写进脚本、日志或回复。

## 输出处理

- 默认使用 `--output json`，stdout 只读取最终 JSON 结果。
- stderr 用于进度、警告和错误事件；不要把 stderr 当成最终业务结果。
- 只需要少数字段时使用 `--pick field1,field2`，字段不存在时以完整安全结果为准。
- `result_meta.complete=false` 时读取 `reason` 和 `next_command`，确认命令安全后继续。
- 下载命令写入本地文件；完成后核对命令返回的大小和校验值。

## 安全规则

- 查询优先。修改、安装、升级、诊断采集前先向用户说明目标和可能影响。
- 只有用户已授权本次修改时才传 `--confirm`。重试同一写请求时复用同一个 `--idempotency-key`。
- 不提供或尝试删除类 CLI；需要删除时说明当前 CLI 不支持，并让用户到受控界面处理。
- 不输出密码、令牌、密钥或被服务端掩码的原值，不尝试从掩码恢复秘密。
- Dump 只允许管理员执行，并可能暂停 JVM、增加 CPU、磁盘和网络负载。其他诊断命令也要展示帮助中的性能提示。
- “已请求取消”不等于执行已停止。继续查询执行状态，只有终态为 `cancelled` 才能说明取消完成。

## 常用排查顺序

1. 查询集群、节点、主机和近期任务状态。
2. 查询对应日志、配置、监控指标、提交历史和命令审计。
3. 使用 `stx diagnostics resource list` 查看可单独采集的诊断资源。
4. 只运行解决当前问题所需的资源；线程快照默认不执行，Dump 仅在必要且已获授权时执行。
5. 对异步操作使用返回的 `next_command`，或使用 `stx execution get|wait <execution-id>` 跟踪真实状态。

命令会随 STX 版本变化。帮助和 `capability list` 是当前环境的准确信息来源，不在本文件中维护完整命令清单。
