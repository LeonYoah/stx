# 实施计划

1. 登记四条主机预检与安装写操作，更新修订号和路由基线。
2. 新增主机安装 CLI，接入根命令并补充双语注释。
3. 增加 CLI 请求与帮助测试，运行相关单元测试。
4. 构建 `dist/stx`，确认软连接使用新二进制。
5. 通过本机 STX 下载或确认 2.3.12 安装包，执行预检和安装。
6. 修正 Agent 的进程标识、PID 查找、心跳监控、`check_process` 和停止逻辑，确保同主机不同安装目录互不影响。
7. 增加双安装目录测试，覆盖进程标识、PID 选择、停止目标和心跳回写。
8. 轮询安装状态，检查目录、版本和现有 2.3.13 进程；真实启动、停止、再启动 2.3.12。
9. 运行 `go test ./...`、`go vet ./...`、数据库兼容检查、License 检查和差异检查。
10. 记录真实验证结果后提交中文 Git 提交。
11. 登记升级模块 8 条 API，增加升级预检查、计划创建、执行和任务等待 CLI。
12. 构建新 `dist/stx`，重启本机 STX 后通过 CLI 将集群 8 升级到 `/tmp/seatunnel-2.3.13-new`。
13. 查询升级任务、步骤和日志，检查新旧目录、两个集群进程、端口和升级后模板任务。
14. 在升级编排侧增加模板任务有限重试，补暂时错误、永久错误和达到最大次数三类测试。
15. 新建独立集群 9，用独立目录和端口重跑安装；发现安装完成后未创建节点时，修正安装后的节点登记和失败状态。
16. 真实安装 `/tmp/seatunnel-2.3.12-retry`，确认自动创建节点并启动，不影响集群 6 和 8。
17. 将集群 9 升级到 `/tmp/seatunnel-2.3.13-retry`，确认模板任务前两次失败、第 3 次通过，步骤重试次数为 2。
18. 修正安装成功后的 `current_step` 和重试日志文案，重新构建并执行最终检查。
