# JVM 诊断命令影响研究

2026-09-13

## 最近更新

2026-09-17

## 官方资料

- Oracle JDK 8 `jcmd` 文档：<https://docs.oracle.com/javase/8/docs/technotes/tools/unix/jcmd.html>
- Oracle JDK 11 `jcmd` 文档：<https://docs.oracle.com/en/java/javase/11/tools/jcmd.html>

## 官方影响说明

- JDK 11 把 `Thread.print` 标为中等影响，实际影响取决于线程数量。`-l` 会额外输出 `java.util.concurrent` 锁信息。
- JDK 11 把 `GC.class_histogram` 标为高影响，实际影响取决于 Java 堆大小和内容。JDK 11 只列出 `-all`，没有 JDK 21 才提供的 `-parallel` 参数。
- JDK 11 把 `GC.heap_dump` 标为高影响，实际影响同样取决于 Java 堆大小和内容。默认会请求一次 Full GC；只有显式使用 `-all`、同时包含不可达对象时才不请求这次 Full GC。
- JDK 8 文档要求通过 `jcmd <pid> help` 查询目标进程实际支持的命令和参数。STX 支持多个 JDK 8 发行版，不能用较新 JDK 的参数替代运行时查询结果。
- `jcmd` 必须在 JVM 所在主机上运行，并使用与目标 JVM 相同的有效用户和用户组。

## 与当前 STX 实现的关系

- 当前线程栈实现是 `jcmd Thread.print -l`，失败后使用 `jstack -l`；该命令在 JDK 11 中被标为中等影响。
- 当前 JVM Dump 实现调用 `jcmd GC.heap_dump`，没有传 `-all`，因此按 JDK 11 文档会请求 Full GC；回退命令 `jmap -dump:live` 同样只保留存活对象。
- 当前尚未实现直方图。如果首版增加 `GC.class_histogram`，应按高影响命令处理，不能把它归入普通只读查询。
- `.hprof` 可能包含任务配置、连接信息和内存中的秘密值。即使生成操作经过授权，文件查询和下载仍需单独鉴权、记录并设置保留时间。

## 已确认规则与待确认项

- `thread-dump` 和 `class-histogram` 不设置诊断专用的调用频率或冷却时间；普通任务队列容量、超时、输出大小、权限、风险确认、幂等和审计规则仍然有效。
- `heap-dump` 保持 R3，只允许明确选择一个节点和一个 SeaTunnel 进程。同一个 JVM 10 分钟内最多开始一次，其他节点或 JVM 不受该间隔影响。
- 限制对象使用目标 JVM 的进程身份识别，至少包含集群、节点、PID 和 JVM 启动时间。目标 JVM 重启后视为新的进程，不能只用可能被系统重复分配的 PID 判断。
- `heap-dump` 的间隔从实际开始采集的时间计算；间隔内的重复请求不执行，并返回稳定错误码、剩余等待秒数和下次允许时间。被拒绝的请求同样写入审计。
- 线程栈、直方图和 JVM Dump 都作为异步资源任务执行。同一个 JVM 同一时间只能执行其中一个诊断命令，不同 JVM 可以并行执行。
- 目标 JVM 已有诊断命令运行时，新请求不排队且不调用 Agent，直接返回 `target_busy`、当前 `execution_id`、资源类型和用于查询或等待现有执行的 `next_command`。
- 互斥目标使用集群、节点、PID 和 JVM 启动时间识别。因 `target_busy` 被拒绝的请求不算实际开始，也不触发 Heap Dump 十分钟限制。
- 三类 JVM 诊断命令在尚未发送给 Agent 时都可以取消，取消后不再下发命令并释放目标 JVM 的互斥占用。
- 线程快照和类直方图已经开始后允许发送取消请求。Agent 需要终止对应工具进程并删除未完成的临时产物，控制端只有在收到停止确认后才能把执行写成 `cancelled`。
- Heap Dump 在 Agent 上实际开始后不可取消，返回 `cancellable: false` 和 `heap_dump_already_started`。杀掉发起操作的 `jcmd` 或 `jmap` 进程不能证明目标 JVM 内部的 Dump 已经停止。
- 命令已经完成时返回 `too_late_to_cancel` 和真实终态。Agent 离线、取消超时或无法确认进程停止时保持 `cancelling`，最终记录取消失败或超时，不能宣称已取消。
- 自动诊断策略默认不执行线程快照、类直方图和 Heap Dump，但配置策略时可以分别勾选需要自动执行的资源。自动执行仍适用人工执行时的目标互斥、Heap Dump 十分钟限制、影响说明、产物保存、审计和真实取消规则。
- 自动策略中的 Heap Dump 选项只能由管理员勾选、保存和启用。线程快照和类直方图按自动策略的普通配置权限处理，不新增持续授权、授权版本或每次自动执行确认。
- 被登记为可能影响目标进程、节点或集群的诊断命令，在确认预览和最终结果中都返回机器可读的影响说明。说明至少包含稳定编码、影响级别、是否可能影响集群、影响范围、可读文案和可能出现的现象。
- `heap-dump` 的文案必须明确说明：操作可能请求 Full GC、暂停目标 JVM，并占用较多磁盘空间和磁盘 I/O，可能影响该节点上的任务和集群运行。线程栈和直方图使用各自登记的影响说明。
- Heap Dump 文件由生成它的 Agent 保存，STX 控制端只保存受控的产物编号、目标、大小、SHA-256、生成时间、过期时间和状态。下载时由 Agent 按块发送，STX 实时中转给客户端，不在控制端长期保存副本。
- 线程栈、类直方图和日志片段等文本结果先脱敏，再按脱敏后的 UTF-8 字节数判断返回方式。不超过 1 MiB 时可以返回完整正文；超过 1 MiB 时，完整脱敏内容作为 Agent 产物保存，响应最多包含 256 KiB 脱敏预览。
- 文本结果只返回预览时，`result_meta.complete` 为 `false`，并包含原因和产物下载命令。Heap Dump 始终只返回产物元数据，不提供正文预览。`--output raw` 同样受这些规则限制。
- 下载只能引用诊断中心签发的产物编号，不能接受客户端提交的节点绝对路径。下载需要单独鉴权和审计，并支持校验及断点续传；Agent 离线、文件缺失或过期时返回稳定错误。
- Agent 节点上的所有诊断产物采用统一保留规则：默认 7 天，管理员可配置为 7 至 30 天。该规则不区分 Heap Dump、日志归档和其他节点诊断文件，也不作用于安装包或源码包。
- 诊断审计只保存目标、实际命令模板、工具、PID、开始结束时间、状态、大小、文件校验值和失败原因，不保存线程正文、直方图正文或堆内容。
