# STX 打包发布说明

## 1. 打包目标

默认 **`split` 布局**（推荐）：

- 版本资产（每次 `v*` 发版，`.github/workflows/release-on-tag.yml`）：
  - 裸二进制：`stx-linux-<arch>`、`stx-agent-linux-<arch>` + `.sha256`
  - 前端：`frontend-standalone-<ver>-linux-<arch>.tar.gz` + `.sha256`
  - `SHA256SUMS`、`install-online.sh`、`download-bundle.sh`
- deps 资产（只在 tag `deps`，手动跑 `.github/workflows/release-deps.yml`；Node / 三件套版本不变不重打）：
  - `node-<major>-<official|glibc217>-linux-<arch>.tar.gz`
  - `observability-prom…-am…-gf…-linux-<arch>.tar.gz`
  - `MANIFEST.json`

兼容：`--layout legacy` 仍可打旧式聚合 tar.gz（可选内置三件套）。

默认端口：API **17800**、前端 **17880**、gRPC **17890**。

---

## 2. 本地打包命令

主脚本：`scripts/package-release.sh`

```bash
# 版本资产：裸二进制 + frontend tarball
scripts/package-release.sh \
  --arch all \
  --layout split \
  --build-frontend

# deps（对应 Release tag deps，不挂到版本 tag）
scripts/package-release.sh \
  --deps-only \
  --arch all \
  --node-major 22 \
  --node-variant official

# CentOS 7 的 Node 18 glibc217 只有 amd64，且不再重打三件套
scripts/package-release.sh \
  --deps-only \
  --no-observability \
  --arch amd64 \
  --node-major 18 \
  --node-variant glibc217

# 旧式聚合包（可选）
scripts/package-release.sh \
  --arch amd64 \
  --layout legacy \
  --bundle-observability both \
  --build-frontend
```

产物目录：`dist/releases/`

## 3. 支持的操作系统与在线 / 离线安装

### 3.0 操作系统

| 发行版 | amd64 | arm64 |
|--------|-------|-------|
| Ubuntu / Debian / Rocky / Alma / CentOS Stream / RHEL 8+ | 支持 | 支持 |
| CentOS 7（glibc 2.17，Node 走 glibc217） | 支持 | **不支持**（无 arm64 的 Node glibc217 构建） |

macOS / Windows 仅适合本地开发，不是一键安装目标。

### 3.1 在线一键

```bash
# 海外（默认 latest，默认带监控）
curl -fsSL https://github.com/LeonYoah/stx/releases/latest/download/install-online.sh | bash

# 国内（gh-proxy 已写进 URL）
curl -fsSL https://v4.gh-proxy.org/https://github.com/LeonYoah/stx/releases/latest/download/install-online.sh | bash
```

可选：`--version v0.0.1`、`--without-observability`、`STX_DOWNLOAD_MIRROR_PREFIX=https://cdn.gh-proxy.org`  
Node / 三件套默认从 Release tag `deps` 下载。

### 3.2 离线 bundle 脚本

先 `ldd --version`、`node -v`。glibc ≤ 2.17 → 组装 `node-18-glibc217`（仅 amd64）；glibc > 2.17 且本机 Node ≥ 18.18 → 不组装 Node；否则组装 `node-22-official`。

```bash
curl -fsSL https://github.com/LeonYoah/stx/releases/latest/download/download-bundle.sh | bash
```

产出 `dist/offline/stx-offline-bundle-*.tar.gz`，拷到离线机 `./install.sh --offline`。

### 3.3 手动点链接

无法跑脚本时，点 README 中的下载链接；国内把链接粘到 [https://gh-proxy.com/](https://gh-proxy.com/) 打开。文件放入 `packages/` 后 `./install.sh --offline`。Node 规则同 3.2。

### 3.4 Docker 全量（Compose）

发版资产：`stx-docker-compose.tar.gz`（`package-release` 已打包；新 tag 后可从 `latest/download` 拉）。

```bash
curl -fsSL https://github.com/LeonYoah/stx/releases/latest/download/stx-docker-compose.tar.gz | tar -xz
cd docker && cp config.example.yaml config.yaml && docker compose up -d
```

| 数据库 | Compose |
|--------|---------|
| MySQL（默认） | `docker compose up -d` |
| SQLite | `docker compose -f docker-compose.sqlite.yml up -d` |
| PostgreSQL | `docker compose -f docker-compose.postgres.yml up -d` |

单容器体验（无监控）：`docker run -d -p 17800:17800 -p 17880:17880 -p 17890:17890 ghcr.io/leonyoah/stx-all-in-one:latest`。

### 3.5 安装后

```bash
/opt/stx/bin/start.sh
/opt/stx/bin/stop.sh
/opt/stx/bin/status.sh
# 或 systemctl restart stx
```

配置文件：`/opt/stx/config.yaml`

## 4. GitHub Actions 流程

### 4.1 main 分支 CI

工作流：`.github/workflows/ci-main.yml` — 测试与前端构建。

### 4.2 tag 发布

工作流：`.github/workflows/release-on-tag.yml`（`v*`）

- 只打包并上传 `stx`、`stx-agent`、frontend tarball
- 不同步上传 Node / 三件套
- 同步发布 GHCR 镜像：`stx-backend` / `stx-frontend` / `stx-all-in-one`

### 4.3 deps 发布

工作流：`.github/workflows/release-deps.yml`（手动 `workflow_dispatch`）

- 上传到 Release tag `deps`，且 `--latest=false`，避免抢走版本最新版
- 在线 / 离线脚本默认 `--deps-tag deps`
- Node、Prometheus、Alertmanager、Grafana 版本不变时不要重跑

## 5. Docker 说明

### 5.1 全量 Compose（推荐）

`deploy/docker/`：一份 `config.example.yaml` + `docker-compose.yml`（MySQL）/ `docker-compose.sqlite.yml` / `docker-compose.postgres.yml`。发版打成 `stx-docker-compose.tar.gz`。

```bash
cp config.example.yaml config.yaml
docker compose up -d
```

### 5.2 all-in-one 单镜像

`stx-all-in-one` 含后端、前端、镜像内 Node，**不含**监控三件套。全量监控请用 Compose。

```bash
docker run -d -p 17800:17800 -p 17880:17880 -p 17890:17890 \
  ghcr.io/leonyoah/stx-all-in-one:latest
```

入口脚本：`.github/docker/all-in-one-entrypoint.sh`
