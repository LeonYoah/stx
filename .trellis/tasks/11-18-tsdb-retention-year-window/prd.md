# 内嵌 tsdb 默认按容量保留 + 时间窗放宽到一年（长窗口按周 / 按月分桶）

内嵌 tsdb 目前默认只保留 31 天，自定义时间窗最长也只有 31 天。按 15s 抓取估算，一般规模的用户一年都写不满 30GiB，
31 天会把存得下的数据提前删掉。这次改成默认只按容量保留，并让各类图表可以查看最长一年的数据。

## 已确认事实（2026-11-18，基于 main `7ee6624b`）

### 存储
- 默认值：`observability.storage.retention: "31d"`，`max_size` 缺省 30GiB（`config.go:321`，`config.example.yaml:238`）。
- `embedts.Options.withDefaults` 会把 `RetentionDuration <= 0` 改回 31 天（`embedts.go:118`），
  所以**现在无法关闭按时间保留**。
- `embedts.Start` 没有设置 `MaxBlockDuration`。tsdb 的默认值是 2h，`db.go:1013` 会把超过它的合并档位截掉，
  所以**块永远是 2h 一个，从不合并**（本地开发库实测确认）。31 天约 372 个块，一年约 4380 个块。
- 超过容量上限时的清理（`tsdb.BeyondSizeRetention`）：
  - 每分钟重新加载块时检查一次，压缩完成后也会检查；
  - 大小 = WAL 与 head 落盘部分 + 从新到旧逐块累加，超过上限的那个块及更旧的块**整块删除**；
  - 只按 tsdb 目录计算，不看磁盘剩余空间。
- tsdb v0.316 提供 `MaxPercentage`（按所在磁盘的百分比计算上限），但它和 `MaxBytes` 同时设置时**只认百分比**，
  没法取两者中较小的那个。
- 容量估算（每条序列每天 5760 点，压缩后每点 1.5–3 字节）：
  - 1 千序列：一年 3–6GB；
  - 5 千序列：约一年写满 30GiB；
  - 2 万序列（容量文档推荐的上限）：3–6 个月写满。
- 内置 tsdb 从未发布过（v1.4.0 的配置里没有 `observability.storage`），**不需要考虑升级兼容**。

### 时间窗
- 后端 `promquery.MaxCustomSpan = 31d`，`ParseWindow` 超出就返回 400。
  首页集群 / 主机 / 作业 / 读写量、集群详情、作业趋势都走它。
- 前端时间控件（`ArcDateRangePicker`）没有跨度限制。选完之后，`HomeDashboard.tsx:176` 和
  `MetricsTrendView.tsx:193` 会把开始时间**静默截断**为"结束时间往前 31 天"，界面上没有任何提示。
- 趋势图步长：`AutoStep` 目标约 240 点 / 序列，候选步长最大 4h（14400s）。超出时就固定用 4h，
  一年会有约 2190 个点。
- 趋势图的速率表达式固定是 `rate(...[5m])` 或 `[1m]`（`cluster.go`、`cluster_detail.go`、`hosts.go`、`jobs.go`、
  `job_timeseries.go`）。步长变成小时或天之后，每个点只反映那一刻前 5 分钟的速率，是稀疏取样，会漏掉峰值。
- 读写量柱状图：
  - 自动粒度：≤6h 用 quarter_hour，≤72h 用 hour，≤62d 用 day，再长用 month；**没有周**。
  - 每个桶、每个指标，以及窗口合计，都按"显示时区的自然日"切开，各发一条 `increase(...[1d])` 即时查询
    （`volumeIncreaseChunks`）。选一年时，按月柱加窗口合计，大约要发 365 × 4 × 2 ≈ 2900 条查询。
  - 响应里已经有 `oldest_sample_ms`（`embedts.OldestSampleTime`）。

## Locked Decisions（用户确认）

1. 默认**只按容量保留**，`retention` 留作可选的时间上限。
2. 自定义时间窗上限**放宽到一年**。
3. 长窗口的读写量**按跨度动态分桶，分到周、月**。
4. 不做升级兼容，直接改默认值。

## Requirements

### R1 默认按容量保留
- `retention` 缺省或为空时表示不按时间删除；`0` 也表示不按时间删除。
- `max_size` 未配置时，默认取 `min(30GiB, 数据目录所在磁盘总容量的 20%)`，启动日志写明最终值和计算依据。
  显式配置时按配置值；显式写 `0` 表示不限。
- `retention` 与 `max_size` 都不限时允许启动，但要记一条 WARN（数据会无限增长）。
- 监控状态页 / API 里的保留期显示"不限"，不能显示空串或 0。

### R2 数据块合并
- 设置 `MaxBlockDuration`：配置了 `retention` 时取 `min(retention/10, 7d)`，未配置时取 7d，且不小于 2h。
- 目的：
  - 一年的数据块数量从约 4380 降到约 60 个；
  - 同时保证超过容量上限时一次删掉的数据不会太多（单个块最长 7 天）。

### R3 时间窗放宽到一年
- 后端自定义窗口上限改为 366 天（含闰年）。
- 预设时间窗新增 `30d`、`90d`、`1y`，首页和作业详情的分段控件同步加上。
- 前端截断改为"可见"：超出一年时截断，并在控件旁边提示"已截取为最近 1 年"。
- 窗口早于最早样本时：
  - 柱状图早于 `oldest_sample_ms` 的桶标记为"无数据"，不能显示 0；
  - 趋势图同理，不画 0 值。

### R4 长窗口趋势图正确取样
- 步长候选补上 6h / 12h / 1d / 2d，长窗口仍保持约 240 点 / 序列。一年窗口步长为 2d，约 183 个点。
- 计数器类面板：速率窗口取 `max(默认窗口, step)`，每个点反映整个步长区间的平均速率，不再是稀疏取样。
- 仪表类面板（内存、使用率等）：步长超过 5 分钟时用 `avg_over_time(x[step])`。
  原本就是峰值语义的面板用 `max_over_time`，按面板逐个确认。
- 在推荐规模下（2 万活跃序列），一年窗口的所有面板都不能触发 `too many samples`，需要容量基准测试证明。

### R5 读写量按周 / 按月动态分桶
- 新增粒度 `week`（显示时区，周一为一周的开始）。
- 自动粒度改为：≤6h quarter_hour、≤72h hour、≤31d day、≤26 周 week，再长用 month。
- 查询成本不能随窗口长度线性增长到上千条：先用一次范围查询拿到逐日增量，再由后端聚合成周 / 月桶和窗口合计。
  一年窗口每个指标只需约 1 条范围查询，加上首尾不完整的日子各 1 条即时查询。
- 首尾不完整的周 / 月沿用现有的 `partial=true`。
- 接口、CLI 的 `granularity` 参数接受 `week`。

### R6 文档与规范
- `config.example.yaml`、`docs/内置监控说明.md`、`install-core.sh` 安装摘要、容量规范 `embedded-tsdb-capacity.md`、
  `engine-events-and-realtime.md` 与 `ui-conventions.md` 里的"31 天"表述，以及 swagger 注释，全部同步更新。
- 如果 #157 已合入，同时更新 `docs/release-notes/unreleased.md`。

## Acceptance Criteria

- [ ] 默认配置启动后，日志显示 `retention=不限`，`max_bytes = min(30GiB, 磁盘 20%)`。
      在 40GB 的磁盘上算出约 8GiB。
- [ ] `retention: "0"` 或留空都不再被改回 31 天；显式配置 `retention: "90d"` 时按 90 天删除。
- [ ] 设置 `MinBlockDuration` 的短块基准测试能观察到块被合并到上限；块时长不超过 7 天。
- [ ] 首页、集群详情、主机、作业趋势、读写量都能选一年的自定义窗口，后端不再返回 400。
      超过一年时前端截断，并有可见提示。
- [ ] 一年窗口下，读写量柱状图为按月分桶（约 12–13 根）。90 天窗口按周分桶（约 13 根）。
      早于最早样本的桶显示为"无数据"。
- [ ] 一年窗口下，读写量单次请求的 PromQL 查询数不超过"指标数 × 3"（用单测或计数器断言）。
- [ ] 一年窗口下，趋势图的步长为 2d，计数器面板的速率窗口不小于步长。
      容量基准测试在 2 万序列下各面板不触发 `too many samples`。
- [ ] CLI：`stx dashboard home volume --granularity week` 可用；预设 `--range 30d|90d|1y` 可用。
- [ ] 文档与规范中不再有"自定义窗口最长 31 天""默认保留 31 天"的过时表述。

## Out of Scope

- 降采样 / 预聚合（recording rules）。这次通过范围查询和速率窗口解决；
  如果容量基准测试在推荐规模下仍然超限，再单独立项。
- 窗口超过一年。
- 历史 Prometheus 数据导入。
