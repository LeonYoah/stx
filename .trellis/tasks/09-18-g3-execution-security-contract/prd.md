# 统一安全执行、任务取消与审计约定

## Goal

为 STX CLI 和后续 API 命令提供一套最小、统一且可验证的安全执行约定。保留诊断、升级、同步、安装和下载各自的业务模型，但让 CLI 面对一致的任务状态、取消结果、风险确认、幂等和审计字段。

本任务不迁移旧任务数据，不新增独立 Scheduler 或 Worker，不把所有业务任务强行合并成一张表。首版优先保证“页面显示的取消状态”和“实际执行是否停止”一致，避免 CLI 或 Agent 误以为危险操作已经结束。

## Requirements

- 建立统一执行协议，至少覆盖执行编号、用户归属、目标、来源请求编号、状态、风险等级、可取消性、结果摘要和错误信息。
- 统一状态至少支持 `pending`、`running`、`cancel_requested`、`cancelling`、`cancelled`、`succeeded`、`failed`；已结束任务不能再次进入运行状态。
- 取消请求必须幂等。收到请求后不能直接返回 `cancelled`，只有实际执行停止并确认后才能返回；无法安全停止时返回明确的不可取消或已过晚原因。
- 任务和审计按用户归属管理，与令牌和机器解耦。令牌只用于识别当前用户，用户被禁用后后续请求立即失效。
- 写操作和可能影响集群的操作统一返回风险提示，并支持服务端二次确认；幂等键重复提交不能产生第二次实际执行。
- 审计记录统一关联用户、请求编号、执行编号、Agent 命令和文件下载，参数与结果摘要必须脱敏，不保存密码、令牌、密钥和配置秘密原文。
- SeaTunnel 任务配置和命令参数继续执行“只写不读”。CLI 的 `raw` 输出不能绕过服务端脱敏。
- 首批接入诊断、升级、同步三类已有异步任务；安装包下载和源码下载暂时只预留公共协议，不在本任务公开新的写命令。
- 不考虑旧任务数据迁移；服务尚未部署，直接使用新协议和新字段。

## Acceptance Criteria

- [x] 诊断、升级、同步任务都能返回统一的执行状态和用户归属信息。
- [x] 取消请求经过 `cancel_requested`/`cancelling` 后，只有实际执行停止才进入 `cancelled`；重复取消结果一致。
- [x] 已完成、已失败、已取消和不可取消的任务不会被错误地重新标记为运行中或成功。
- [x] 同一用户重复提交相同幂等键不会重复启动实际操作；不同用户不能读取或取消他人的任务。
- [x] 风险操作在缺少确认时不会执行，并返回风险等级、影响说明和确认方式。
- [x] 审计能按用户查询任务创建、取消、Agent 命令和文件下载，并能通过请求编号关联同一调用链。
- [x] 审计、日志、API、CLI 和诊断结果中不出现密码、令牌、密钥或任务配置秘密原文。
- [x] 现有模块的单元测试、接口测试和 CLI 契约测试覆盖上述状态迁移、权限、幂等、脱敏和审计规则。

## Confirmed Scope

- 首版接入诊断、升级、同步三类已有异步任务。
- 安装包下载和源码下载只复用公共协议，本任务不新增相关写命令。
- 诊断任务只在安全步骤边界完成取消，不宣称能够中断 Agent 上已经开始的命令。
- 升级任务只允许在尚未进入实际执行时取消；进入实际执行后返回明确的不可取消原因。
- 同步任务调用 SeaTunnel 停止接口或本地 Agent 停止命令，确认停止后才进入 `cancelled`。

## Out of Scope

- 不新增 Agent 单命令取消协议。
- 不处理旧任务和旧审计数据迁移。
- 不接入安装、安装包下载、插件下载和源码下载任务。
- 不实现审计导出。
- 不实现调试工作台共享编辑权限；本任务只处理运行实例和审计的用户归属。
