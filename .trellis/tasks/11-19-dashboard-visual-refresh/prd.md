# 首页大盘视觉改版：指标栏与作业指标页签

## 背景

用户反馈首页大盘「太丑、没质感」，并给了 Arc 的 metrics-dashboard 作为参考
（<https://uiarc.dev/components/screens/metrics-dashboard>：一行 KPI 页签驱动下面一张图）。
对照本地实例截图（2026-11-19，`/dashboard` 与 `/dashboard?tab=jobs`），问题集中在：

1. **顶部 7 张指标卡**（`DashboardKpiRow`，7 个独立的 Arc `MetricCard`）：
   - 每张卡自带边框、`--radius-surface`（34px）圆角和 `--shadow-resting`，高约 158–170px，数值只占一小块，整排又重又散；
   - 单位与数字同字号（「0行/秒」「0秒」「0行」）；
   - 「失败作业」右上角的「昨日 0」把标题行撑高，数字比其他卡低一截；「数据量」说明折成两行，底边不齐；
   - 异常时（失败 > 0、CDC 超阈值、告警为严重）数字没有任何强调，只靠右上角小胶囊。
2. **「作业」页签**（`JobsTab`）：
   - 顶部指标与「全局吞吐」图互不联动，图表另带一排「写入 行/秒 / 读取 行/秒 / 写入 字节/秒 / 读取 字节/秒」分段控件；
   - 6 个面板同样的边框、底色和标题字号，主图与次要图没有主次；
   - 窗口内没数据时，每个面板都是一个约 240–300px 高的大空框，整页重复出现「该时间窗内没有数据」。
3. **区块页签**（集群 / 作业 / 主机 / 平台 / 作业列表）被父级 `flex-col` 拉成整条宽栏，和指标栏抢视觉重心。
4. **「需要处理」横条**没有事项时仍是一个带边框的整行框，只写「暂无需要处理的事项」。

效果图（改前截图 + 改后示意，示例数据）已在对话中给用户确认方向。

## 约束

- **只用 Arc 免费组件和设计变量**。metrics-dashboard 是 Arc Pro，只作视觉参考：不安装 `@uiarc-pro`、不复制它的源码，
  也不照抄它的像素细节（spec `ui-conventions.md` §14、AGENTS.md「不要手写或仿造 Pro 组件」）。
- **不改 `components/arc/` 下的源码**。需要的样式差异在 STX 自己的组件里用 Tailwind / CSS 变量实现。
- **不改后端接口与 CLI**：本任务用到的数据现有接口都已返回（见 design §2）。`stx dashboard home summary|jobs` 不受影响。
- 与 PR #163 的关系：#163 规定「大盘只对齐交互组件，不改布局」。本任务专门负责大盘的指标栏、作业页签和面板层级；
  #163 对齐层的四类组件（确认、下拉、更多菜单、状态标签）不在本任务范围，两边不重复改同一处。
- 遵守 `ui-conventions.md` §16 已有约定：一个指标一种图、`colorForLabels` 语义色、首页时间走 `lib/timezone`、零塌陷加载。

## 范围

### 做
1. **顶部指标栏**：7 张独立卡改成一条指标栏（一个底板、单元格细线分隔），每格保留现在的跳转目标与 `data-testid`。
2. **数字排版**：数值 + 量级（`48.2K`）大号，计量单位（`行/秒`、`秒`、`行`）小号浅色；说明固定一行，超出截断并给 `title`。
3. **异常强调**：用已有字段给数值染色（失败 > 0、CDC 超阈值、严重告警 > 0、集群有异常 → 危险色；集群只有降级 → 警告色）。
4. **「作业」页签吞吐面板改成「指标页签 + 一张图」**：4 个吞吐指标各占一格（窗口均值 + 峰值），选中哪格图就画哪条；
   去掉原来的分段控件。图表仍是现在的 Arc `BrushChart`（保留拖选缩放与事件标注）。
5. **面板层级**：抽一个 `DashboardPanel`，分「主面板 / 次要面板」两档样式；5 个页签文件里重复的面板 class 统一替换。
6. **作业页签空面板**：窗口内没有数据的次要面板缩成一行矮条（标题 + 「该时间窗内没有数据」），不再是大空框。
7. **区块页签**恢复 Arc `Tabs` 的自然宽度（不再被拉满整行），不改 Arc 样式。
8. **「需要处理」**：没有事项时去掉外框，只留一行浅色文字。
9. spec 与测试同步（见验收标准）。

### 不做
- 新增涨跌数据：吞吐指标「较上一时间窗」的变化需要后端新增对比查询和 CLI 参数，列为后续任务（design §8）。
- 集群 / 主机 / 平台 / 作业列表页签的布局与图表：只换成 `DashboardPanel` 样式，不动内容和结构。
- 作业详情「指标」页签：可以复用本任务的指标页签组件，另开任务。
- 「CDC 延迟」不做成第 5 个吞吐页签：`/dashboard/home/jobs` 没有全局 CDC 时序，它已有「CDC 延迟 Top 8」面板。
- 页面头部（`WorkspaceHeader`、时间窗、刷新）不改。

> **追加范围（第二轮，design §11）**：用户复看后认为头部「全部集群」下拉与集群页签大卡片仍和条带视觉不统一，追加：
> 头部范围选择 shadcn `Select` → Arc `Combobox`（可搜索，`all` → `clusterId: undefined` 与 `home-scope` testid 不变）；
> 集群页签 Arc `RadioCards` → `ClusterScopeStrip` 分隔格选择条（`radiogroup` / `radio`、roving tabindex 与 `ThroughputTabs` 共用
> `use-roving-keys`、健康徽标与描述信息不丢）；顺带清理 dev overlay 告警（React 19 key、Radix Dialog 标题、GSAP 空选择器）。

## 验收标准

- [ ] AC1 指标栏：宽屏（≥1280px）一行 7 格、高度 ≤ 96px；单元格之间只有 1px 分隔线，没有独立卡片的圆角与阴影。
      `lg` 4 列、`sm` 2 列、更窄 1 列时，换行处分隔线连续、末行不出现色块。
- [ ] AC2 每格整格可点击，跳转目标与现在一致；`home-kpi-row`、`home-kpi-{running|write|cdc|failed|volume|clusters|alerts}`
      这些 `data-testid` 保留（`e2e/dashboard.spec.ts` 不改即通过）。
- [ ] AC3 数值与计量单位分开排版：单位字号明显小于数字且为次要文字色；数字用等宽数字，轮询刷新时不抖动。
- [ ] AC4 说明只占一行，过长截断并带 `title`；所有格子的标题、数字、说明三条基线对齐（失败作业不再被胶囊撑低）。
- [ ] AC5 写入速率的涨跌仍按 `trendChangePercent(write_trend)` 显示，涨绿跌红；失败数与「昨日 N」保持中性文字（不带正负号）。
- [ ] AC6 失败作业 > 0、CDC ≥ 阈值、严重告警 > 0、集群有异常（unhealthy > 0）时数值为危险色；集群只有降级时数值为警告色；其余为前景色。
- [ ] AC7 「作业」页签：吞吐面板顶部 4 个指标格（写入 / 读取 × 行 / 字节），显示窗口均值与峰值；点格子或在格子上按
      ←/→ 切换图表序列；原「吞吐指标」分段控件不再出现；`BrushChart` 的拖选缩放与事件标注照常。
- [ ] AC8 窗口内无数据的次要面板高度 ≤ 48px，显示面板标题与「该时间窗内没有数据」；有数据后恢复正常高度。
      首次加载仍走骨架，不出现高度塌陷（零塌陷）。
- [ ] AC9 区块页签按内容宽度显示；「需要处理」无事项时没有外框。
- [ ] AC10 深浅两套主题下截图对比通过（指标栏、作业页签有数据 / 无数据各一张），附在 PR。
- [ ] AC11 `ui-conventions.md` §16 与一致性检查项更新；`DashboardKpiRow` / `JobsTab` 单测更新，新增单测见 implement.md；
      `pnpm exec tsc --noEmit`、`pnpm test`、`e2e/dashboard.spec.ts` 通过。
