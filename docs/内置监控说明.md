# STX 内置监控说明

STX 自带监控：指标采集、存储、查询、趋势图和指标告警都在 STX 后端进程里完成，**不需要另外安装或维护任何监控组件**。
首页大盘、集群 / 作业趋势、作业详情的「趋势」页签、诊断报告里的指标快照和策略中心的指标告警都用这份数据。

## 采集什么

| 来源 | 内容 | 方式 |
| --- | --- | --- |
| SeaTunnel 引擎 | 每个受管集群的每个在线节点的引擎指标（JVM 堆 / 非堆、GC、线程、CPU、FD、作业线程池、Hazelcast 分区与执行器、作业状态计数等） | 后端按 `scrape_interval`（默认 15 秒）访问节点的 `seatunnel_metrics.path`（默认 `/hazelcast/rest/instance/metrics`），不需要在节点上装任何东西 |
| STX 作业 | 每个作业的读写条数 / 字节、提交条数、CDC 延迟、Checkpoint 耗时与失败次数、算子忙碌度、边背压、表级读写量 | 后端在作业状态对账时直接写入，作业结束时写入最终值后停止 |

节点不可达时，该节点在可用性图上显示为不可用，策略中心「引擎指标采集」能力卡给出原因。

## 配置

`config.yaml` 的 `observability` 段（默认值见 `config.example.yaml`）：

```yaml
observability:
  enabled: true              # 总开关，默认开启
  storage:
    dir: "data/tsdb"         # 数据目录，相对安装目录
    retention: "31d"         # 保留时长，支持 s/m/h/d/w/y
    max_size: 32212254720    # 存储上限（字节），默认 30GiB；显式写 0 表示不限
  scrape_interval: "15s"     # 引擎指标采集间隔
  eval_interval: "15s"       # 指标告警评估间隔
  query_timeout: "8s"        # 单次查询超时
  max_samples: 50000000      # 单次查询最多加载的样本数
  seatunnel_metrics:
    path: "/hazelcast/rest/instance/metrics"
    probe_timeout_seconds: 2
  remote_ingest:             # 外部告警接入，见下文
    path: "/api/v1/monitoring/alertmanager/webhook"
    token: ""
```

修改后重启 STX 生效。

### 保留时长与磁盘

- 数据按 `retention` 与 `max_size` 两个条件删除，先到哪个按哪个。默认能看最近 31 天，首页「每日 / 每月读写量」也受此限制。
- 想看更久的历史，同时调大 `retention` 和 `max_size`。
- 占用大致与「节点数 × 引擎指标数 + 作业数」成正比，几十个节点的规模通常在几 GB 以内。

### 关闭

`enabled: false`（或安装时加 `--without-observability`）后：不再采集与评估，趋势图显示「可观测性未开启」，
指标类告警策略不可用；集群卡片、节点表、作业列表、运行日历、平台健康告警和作业告警不受影响。

## 告警

- **内置规则**：引擎指标端点不可达、节点状态异常、分区不安全、作业线程池积压 / 拒绝、JVM 堆、进程 CPU、GC 耗时、FD 使用率、线程死锁等，
  开箱即用，触发后进入告警中心并按通知路由投递。
- **指标模板策略**：在策略中心选择 CPU、内存、FD、失败作业等模板，只需设置阈值、窗口与通知渠道。
- 告警的去重、冷却重发、静默、恢复通知与平台健康告警一致；STX 重启后，处于「持续中」计时的告警会继续计时，不会从头开始。

## 外部告警接入

外部系统可以把告警推给 STX，统一进入告警中心和通知链路。接口兼容 Alertmanager Webhook 格式：

```
POST <STX 地址><remote_ingest.path>
Authorization: Bearer <remote_ingest.token>
Content-Type: application/json
```

- 配置了 `token` 时必须携带对应的 `Authorization` 头，否则返回 401。
- `token` 为空时不校验（兼容已接入的系统），STX 启动时会记一条警告日志。对公网可达的部署请务必配置 `token`。
- `enabled: false` 时该接口不可用（404）。

## 从旧版本升级

旧版本通过外部的 Prometheus / Alertmanager / Grafana 提供监控。升级到内置监控后：

- 安装脚本不再下载、启动这三个组件；升级时如果检测到旧的 `observability/` 目录会提示一次，目录和数据**保留不删**，确认不需要后可手动删除。
  旧版本留下的进程会在下次执行 `bin/stop.sh`（或 `systemctl stop/restart stx`）时一并停止。
- 历史监控数据不自动迁移，升级后从零开始积累。若必须查看旧数据，可把 `storage.dir` 临时指向旧的 Prometheus 数据目录（同为同一存储格式）。
- 旧配置文件里的 `observability.prometheus` / `alertmanager` / `grafana` 段会被忽略，不影响启动，可以删掉。
- 旧的安装参数（`--with-observability`、`--prometheus-port`、`--alertmanager-port`、`--grafana-port`）和 `bin/start.sh --observability ...` 仍可传入，但不再起作用。
- Docker Compose 部署只剩 STX 前后端与数据库容器，监控数据在 `data/stx/tsdb`。
- 原来指向 STX 的外部 Alertmanager 仍可继续推送到外部告警接入接口，路径不变，建议补上 `token`。

## 常见问题

**趋势图显示「监控数据暂不可用」**：数据目录无法打开（权限、磁盘满）或查询超时。查看 `logs/backend.log` 中 `[Observability]` 开头的日志。

**某个节点的图是空的**：确认节点在线、配置了 Hazelcast 端口，且 STX 能访问 `http://<节点 IP>:<Hazelcast 端口><seatunnel_metrics.path>`。

**作业趋势没有数据**：作业趋势来自作业状态对账，作业需要处于运行中；已结束的作业可以在作业详情里按「作业全程」查看历史。
