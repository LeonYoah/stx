# 增强：每日 / 每月 / 指定时间读写量

父任务：`11-14-home-monitoring-dashboard`。排期：P1–P4 验收完成之后。

## Locked Decisions（2026-11-16 用户确认）

- **只用内嵌 tsdb**（Prometheus 存储引擎），不在 STX 数据库建汇总表。
- 回看范围（2026-11-16 随内嵌可观测任务更新）：保留期由 `observability.storage.retention` 决定，默认 **31 天**，另受
  `storage.max_size`（默认 30GiB）约束，超限时会更早删块。因此「能看多远」**以 tsdb 实际最早样本时间为准**，不按配置值推算；
  需要多个月历史的用户自行调大两项配置。升级到内嵌版是破坏性变更，历史从升级当天重新累积。
  可观测性关闭或内嵌存储不可用时无数据（按 `reason` 统一空态）。

**依赖**：内嵌可观测 P2 已合并（`stx_job_*` 写入 tsdb）；需要内嵌包提供「最早样本时间」查询（`embedts` 暴露
`OldestSampleTime()`，取 `db.Blocks()` 首块与 Head 的最小时间），若内嵌任务未提供则本任务补上。

## Requirements

- 指标卡新增「读写量」：主数字为当前时间窗（含自定义区间）的写入行数，副标题「今日 X · 本月 Y」（本月早于最早样本时注明「自 M 月 D 日起」）。
- 作业页签新增「数据量」柱状图：按日 / 按月切换；读 / 写、行 / 字节切换；可按集群或任务拆分。
- 后端用 `increase(stx_job_*_total[...])`：按日用显示时区零点对齐的 `step=1d` 区间查询；按月对每个自然月做一次即时查询（月长不等）。
  计数器重置（作业重启）由 `increase` 处理。作业终态时最后一次增量：已要求内嵌 P2 在删除作业序列前同步补写一次终值
  （否则最多丢一个抓取周期的增量，短于 15 秒的批作业可能完全没有样本），本任务验收时核对。
- 接口与 CLI（如 `stx dashboard home volume --granularity day|month`）。

## Acceptance Criteria

- [ ] 指定区间写入量与该区间内各作业「累计写入」差值之和一致（抽样核对，允许 Prometheus 外推误差）。
- [ ] 跨日 / 跨月边界按显示时区对齐。
- [ ] 超出最早样本时间时明确提示起始日期，不给出误导性的 0。
- [ ] 短批作业（运行 < 15 秒）的写入量计入日 / 月统计。
